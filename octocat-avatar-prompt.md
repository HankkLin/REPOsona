# Octocat Avatar Prompt

Image-generation prompt for creating a repository's avatar: GitHub's Octocat, restyled to represent the repo. Fill in the bracketed repository context and attach the creator's profile picture.

## Prompt

Create a circular profile avatar of GitHub's Octocat, restyled to represent the repository described below. Keep the Octocat clearly recognizable: the cat head with pointed ears, the friendly face and the tentacle arms.

### Repository context

* Name: [repo name]
* README summary: [3–5 sentence summary]
* Tech stack: [main languages/tools]
* Purpose / domain: [what it does and who it's for]
* Activity level: [commits, stars, how active]
* Contributors: [solo, small team, large community; who they are]
* Tone: [playful, experimental, academic, professional, etc.]

### Character concept (most important)

Don't default to a programmer, engineer or hacker. Look past the code and ask what the project is really about: what real-world problem, craft or community it serves. Dress the Octocat as the person who lives in that world.

* A weather data API becomes a storm chaser or meteorologist.
* A music theory library becomes a conductor or jazz musician.
* A recipe-scaling CLI becomes a pastry chef.
* A map-rendering engine becomes a cartographer or explorer.
* An accessibility toolkit becomes a sign-language interpreter or guide.
* A database optimization tool becomes a librarian or archivist.
* A security scanner becomes a locksmith or detective.

For purely technical projects with no obvious domain, use a metaphor for what the code does: a caching layer is a squirrel storing acorns, a parser is a translator, a scheduler is a train conductor.

### Character design

* Role and outfit: Use the career or persona chosen above, with clothing true to that role.
* Accessories: Use 1–2 props that reveal the nuanced core of the project, not generic tech items. Avoid laptops, code brackets, terminals and gears unless they truly are the subject.
* Colors: Base the palette on the project's mood and domain, with a subtle nod to the tech stack's signature colors.
* Energy: Very active repos get a confident, lively expression and richer detail. Small or quiet repos get a calm, simple look.
* Team size: A solo project gets a personal, individual look. A big community gets subtle team cues, like a uniform, a badge or pins.
* Creator touch: Borrow 1–2 distinctive elements from the attached profile picture, such as a signature color, glasses, hat, hairstyle or pet. Add them only if they fit naturally, and don't replicate the person's face.

### Art style (pick from the project's tone and scale)

* Playful, hobby or creative projects: soft claymation. Rounded shapes, fingerprint texture, matte finish, warm lighting.
* Experimental, indie or student projects: hand-drawn sticker illustration. Bold outlines, flat colors.
* Retro, gaming or nostalgic projects: clean pixel art with a limited palette.
* Mid-size tools or open-source libraries: crisp flat vector with subtle gradients.
* Large-scale or enterprise tech: polished 3D render. Glossy materials, studio lighting, refined detail.

### Composition

* Square 1:1 image designed to be cropped to a circle.
* Show the upper half of the body only, from the chest up, like a portrait bust.
* Center the head slightly above the middle. Keep the ears and accessories at least 10% inset from the edges so nothing gets cut off by the crop.
* Use a simple, solid or softly graded background that fills the frame edge to edge.
* Use a strong silhouette and clear contrast so it reads at small sizes.

### Text

* Use no text by default. If text is essential, allow at most one short word or the repo's initials on a small badge.
* No logos, watermarks or captions.
